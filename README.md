# Физика — курс, чат и платформа

Первый каркас платформы подготовки к ОГЭ по физике:

- открытая теория, презентации и задачи;
- peer-to-peer canvas для уроков физики;
- закрытый интенсив с домашними работами и обратной связью.

Сейчас реализованы посадочная страница со счётчиком до ОГЭ по физике и MVP
совместной физической доски. Дата 10 июня 2027 года взята из проекта расписания
и прямо обозначена на странице как предварительная.

## Физический canvas

Доска доступна по адресу `/canvas/` и уже поддерживает:

- бесконечную доску Konva с pan, zoom и мобильными жестами;
- физические фреймы с групповым перемещением содержимого;
- бруски, шары, блоки, поверхности, пружины и предметные схемы;
- силы, которые прикладываются только к телам и следуют за ними;
- редактирование размеров, подписей, цветов и физических параметров;
- рамочное и множественное выделение;
- симуляцию выбранного фрейма через Matter.js;
- отмену и повтор действий, очистку и локальное сохранение;
- синхронизацию двух участников по WebRTC DataChannel.

Текущее состояние архитектуры, известные ограничения и план до завершения
механического MVP описаны в [`docs/PHYSICS_CANVAS.md`](docs/PHYSICS_CANVAS.md).

### Как работает совместная сессия

После соединения состояние доски и курсоры передаются напрямую между браузерами.
Небольшой WebSocket-сервер нужен только для signaling: обмена WebRTC offer,
answer и ICE-кандидатами. GitHub Pages размещает статический интерфейс, но не
может выполнять этот сервер.

Для проверки на одном компьютере откройте два терминала:

```bash
npm run dev
npm run signal
```

Откройте canvas, нажмите «Поделиться» и создайте комнату. Вторую вкладку откройте
по полученной ссылке.

Для урока в одной локальной сети запускайте интерфейс на всех сетевых адресах:

```bash
npm run dev:lan
npm run signal
```

Открывайте доску по LAN-адресу компьютера преподавателя, а не через `127.0.0.1`,
чтобы ссылка была доступна ученику. Порты по умолчанию: Astro — `4321`,
signaling — `8787`.

Для работы через интернет signaling-сервер нужно развернуть с TLS и использовать
адрес `wss://`. В production также понадобится TURN-сервер: одного STUN может
быть недостаточно в строгих корпоративных и мобильных сетях.

## Локальный запуск

Требуется Node.js 24. Он уже установлен в системе; устанавливать его в проект
или добавлять в зависимости не нужно. Все `npm run`-команды проекта сами
переключаются на Node 24 через `scripts/node24`.

```bash
nvm exec 24 npm install
npm run dev
```

Проверка и сборка:

```bash
npm run check
npm run build
npm run preview
```

Статическая сборка создаётся в `dist/`.

## GitHub Pages

Публикация запускается автоматически при каждом push в `main` через
`.github/workflows/deploy.yml`; GitHub Actions собирает сайт на Node 24.

### Как опубликовать изменения

После проверки локально достаточно отправить коммит в основную ветку:

```bash
git push origin main
```

Отдельная команда деплоя не нужна: GitHub Pages сам соберёт и опубликует сайт.
