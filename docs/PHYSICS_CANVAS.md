# Физический Canvas: состояние, архитектура и план

Документ фиксирует состояние физической доски на 16 ноября 2026 года и служит
точкой входа для следующего разработчика или агента. Базовый коммит описанного
состояния: `30c95ca`.

## 1. Текущий этап

Текущий продуктовый этап — **Canvas Mechanics MVP**: редактор механических схем,
в котором преподаватель создаёт отдельные физические фреймы, размещает тела и
силы, а затем запускает симуляцию выбранного фрейма.

На этом этапе не нужно пытаться одновременно превратить доску в универсальный
симулятор всех разделов физики. Тепловые, электростатические и атомные модели
остаются важным направлением, но развиваются после стабилизации механического
ядра.

## 2. Что уже работает

### Доска и интерфейс

- бесконечная рабочая область на Konva.js;
- pan, zoom относительно указателя, масштабирование кнопками и pinch-жест;
- светлая и тёмная темы;
- фиксированная мобильная панель инструментов;
- отдельная мобильная кнопка запуска симуляции;
- полная очистка доски с возможностью отмены;
- undo/redo и локальное сохранение в `localStorage`;
- свободное рисование, текст и формулы как текстовые объекты;
- общая указка и удалённый курсор участника;
- рамочное и множественное выделение, Shift-выделение и групповое перемещение.

### Фреймы

- физические объекты создаются только внутри физического фрейма;
- перемещение фрейма перемещает все дочерние объекты;
- удаление фрейма удаляет его содержимое;
- симуляция запускается только для выбранного фрейма;
- одновременно активен не более чем один симулируемый фрейм;
- кнопка запуска есть в панели, внутри фрейма и на мобильном экране.

### Объекты и редактирование

- брусок, шар, неподвижный и подвижный блок;
- гладкая, шероховатая и наклонная поверхность;
- нить, пружина, диполь, атом, орбитальная схема и тепловая ёмкость;
- подписи, цвет границы, масса, коэффициент трения, угол и другие параметры;
- изменение размера бруска, шара и фрейма за маркер;
- пропорциональное изменение размера с Shift;
- контекстный tooltip бруска и шара: размеры, цвет и удаление;
- тела притягиваются к горизонтальным и наклонным поверхностям;
- брусок принимает угол поверхности; угол передаётся в Matter.js.

### Силы и пружины

- сила может быть приложена только к бруску или шару;
- начало силы следует за родительским телом;
- конец вектора редактируется отдельным маркером;
- длина вектора переводится в значение силы с выбранным масштабом;
- поддерживаются Н, кН и МН;
- новые векторы силы создаются оранжевыми;
- пружина рисуется протягиванием и редактируется за оба конца;
- конец пружины можно закрепить на ближайшем теле;
- закреплённая пружина следует за телом;
- настраиваются жёсткость и длина покоя.

### Механическая симуляция

- Matter.js инкапсулирует расчёты выбранного фрейма;
- поддерживаются гравитация, столкновения, масса, упругость и трение;
- нарисованные силы прикладываются к родительским телам;
- поверхности создаются как статические тела с углом и трением;
- пружины создаются как `Matter.Constraint`;
- состояние можно поставить на паузу и сбросить к исходному снимку.

### Совместная сессия

- состояние доски и курсоры передаются через WebRTC DataChannel;
- WebSocket-сервер используется только для signaling;
- локальная сессия запускается командами `npm run dev` и `npm run signal`;
- модель данных, а не дерево Konva, является передаваемым состоянием.

## 3. Архитектура

```text
UI Astro / DOM
  └── physics-board.ts — сценарии, инструменты, история, сохранение, WebRTC
        ├── PhysicsScene — предметная модель и связи объектов
        ├── KonvaBoardRenderer — камера, слои, hit testing и отрисовка
        └── MatterFrameEngine — механика одного выбранного фрейма
```

Главный принцип: **Konva и Matter не являются источником истины**. Источник
истины — массив типизированных `BoardObject`. Это позволяет сохранять сцену,
передавать её другому участнику, делать undo/redo и в будущем менять renderer
или физический движок независимо от формата данных.

### Основные файлы

| Файл | Ответственность |
| --- | --- |
| `src/pages/canvas.astro` | DOM-интерфейс, панели, диалоги и контейнер Konva |
| `src/styles/canvas.css` | адаптивная компоновка и оформление интерфейса |
| `src/scripts/physics-board.ts` | orchestration редактора и совместной сессии |
| `src/scripts/physics/model.ts` | `BoardObject`, сущности, границы, связи и перемещения |
| `src/scripts/physics/konva-board-renderer.ts` | `Stage`, слои, камера и визуальные узлы |
| `src/scripts/physics/matter-frame-engine.ts` | адаптер сцены фрейма к Matter.js |
| `server/signaling.mjs` | знакомство WebRTC-участников через WebSocket |

### Слои Konva

- `gridLayer` — виртуальная сетка, перестраиваемая относительно камеры;
- `contentLayer` — фреймы и предметные объекты;
- `overlayLayer` — рамка выделения и локальный/удалённый курсоры.

DOM остаётся правильным местом для панелей, tooltip, полей ввода, модальных окон
и будущего KaTeX. Не переносить интерфейсные контролы внутрь canvas без причины.

### Координаты

Координаты `BoardObject` хранятся в мировом пространстве. Камера хранит только
`x`, `y` и `scale`; экранные координаты вычисляет renderer. Не записывать
координаты камеры в физические объекты.

### Иерархия

- `frame` — корневая сущность физической сцены;
- обычный объект содержит `parentId` фрейма;
- вектор силы содержит `parentId` тела;
- пружина содержит `parentId` фрейма и `targetId` закреплённого тела.

При изменении этой схемы необходимо проверить перемещение, удаление, сохранение,
WebRTC-синхронизацию и миграцию старых данных.

### Сохранение

- ключ браузера: `physics-board-v1`;
- сохраняется массив `BoardObject`;
- входящие и сохранённые данные проходят через `normalizeObjects`;
- старые сцены без фрейма мигрируют в один автоматически созданный фрейм;
- `Konva.Stage.toJSON()` намеренно не используется.

## 4. Важные ограничения текущей реализации

- в `physics-board.ts` ещё остался неиспользуемый старый SVG-renderer; он не
  выполняется, но должен быть удалён при ближайшем техническом рефакторинге;
- формулы пока рисуются обычным текстом Konva, а не KaTeX;
- автоматических тестов модели, сериализации, камеры и физики пока нет;
- полноценный визуальный QA на телефонах после миграции Konva не проводился;
- WebRTC-сессия рассчитана на двух участников и не решает конфликты параллельного
  редактирования;
- signaling и TURN не входят в статический GitHub Pages deployment;
- нить и подвижный блок пока являются преимущественно визуальными объектами, а
  не полноценной системой связей Matter.js;
- атом, орбита, диполь и тепловая ёмкость сейчас являются редактируемыми
  иллюстрациями, но не завершёнными физическими симуляциями;
- коэффициент трения поверхности участвует в Matter.js, но наглядный разбор сил
  трения и режим покоя/скольжения ещё не реализован;
- нет импорта/экспорта сцены отдельным JSON-файлом и явной версии схемы данных.

## 5. План до завершения Canvas Mechanics MVP

Пункты расположены в рекомендуемом порядке. Это ближайший обязательный объём,
к которому следует вернуться при продолжении разработки.

### Этап A. Стабилизация и технический долг

1. Удалить старые функции SVG-renderer и неиспользуемые SVG-стили.
2. Разделить перегруженный `physics-board.ts` на контроллеры инструментов,
   history/storage и collaboration.
3. Добавить версию схемы состояния и миграции между версиями.
4. Добавить экспорт/импорт сцены в JSON.
5. Добавить тесты для `PhysicsScene`, связей сил/пружин, удаления фрейма,
   сериализации и преобразований камеры.
6. Провести ручной QA desktop/mobile: мышь, touch, pinch, tooltip, toolbar,
   создание и запуск нескольких фреймов.

### Этап B. Завершение редактора механики

1. Сделать единый контекстный inspector для всех предметных объектов.
2. Добавить групповое изменение цвета, удаление и при необходимости масштаба.
3. Довести resize: ограничения, пропорции, корректная работа повёрнутого бруска.
4. Добавить snapping и направляющие при перемещении объектов.
5. Перевести формулы на KaTeX через DOM-overlay, сохранив мировую привязку.
6. Добавить понятные пустые состояния и подсказки для первого фрейма.

### Этап C. Завершение механической симуляции

1. Реализовать физические нити, неподвижные и подвижные блоки через constraints.
2. Уточнить модель трения: трение покоя/скольжения и связь с поверхностью.
3. Отделить изображённую силу от вычисляемой силы реакции/трения; явно показать,
   какие силы задаёт пользователь, а какие рассчитывает модель.
4. Добавить параметры упругости, сопротивления и начальной скорости тел.
5. Добавить отображение скорости, ускорения и результирующей силы.
6. Проверить размерности и коэффициенты преобразования Ньютонов в Matter force;
   убрать учебно-демонстрационные коэффициенты из UI-логики в физический адаптер.
7. Добавить контролируемый шаг, паузу и скорость времени симуляции.

### Критерии готовности этапа

- учитель собирает типовую задачу по механике без выхода из фрейма;
- силы, поверхности, пружины, нити и блоки ведут себя предсказуемо;
- симуляция одного фрейма запускается и сбрасывается без влияния на остальные;
- сохранённая сцена восстанавливается и может быть экспортирована;
- основные сценарии покрыты тестами;
- интерфейс проверен на ширинах 375, 475, 768 и desktop;
- сборка проходит командами `npm run check` и `npm run build`.

## 6. Последующие этапы, не входящие в ближайший MVP

### Тепловая модель

- каталог газов, жидкостей и твёрдых материалов;
- масса, температура, теплоёмкость и агрегатное состояние;
- тепловой баланс между средой и помещёнными телами;
- плавление, кристаллизация, кипение и конденсация;
- визуализация скорости и цвета частиц;
- отдельный `ThermalFrameEngine`, не встроенный в Matter.js.

### Электростатика

- заряд тела, электрическое поле и закон Кулона;
- вычисляемые электростатические силы;
- диполи и поляризация;
- отдельный модуль расчётов поверх общей модели сцены.

### Атомные и орбитальные схемы

- таблица элементов и автоматическое определение элемента по числу протонов;
- корректные обозначения `A`, `Z` и заряда;
- варианты Солнце—Земля, Земля—Луна и Земля—спутник;
- параметры кругового движения и визуализация центростремительных величин.

### Масштабирование совместной работы

- роли преподавателя и ученика;
- больше двух участников;
- операции/версии вместо пересылки полного состояния;
- разрешение конфликтов, presence и восстановление соединения;
- production signaling и TURN.

## 7. Правила продолжения разработки

1. Сначала менять предметную модель, затем renderer и физический адаптер.
2. Не хранить единственное состояние внутри Konva или Matter.
3. Любая сила должна ссылаться на физическое тело.
4. Симуляция всегда запускается для конкретного фрейма.
5. Новые типы симуляций оформлять отдельными engine-классами.
6. Изменения формата `BoardObject` сопровождать нормализацией и миграцией.
7. Проверять mobile layout и отсутствие горизонтальной прокрутки.
8. Не добавлять React только ради Canvas: текущему Astro-модулю достаточно
   Konva + TypeScript, пока не появится конкретная потребность.

## 8. Команды проверки

Используется установленный Node.js 24 через проектные скрипты:

```bash
npm run check
npm run build
```

Для локальной совместной сессии:

```bash
npm run dev
npm run signal
```

Деплой выполняется только через `git push origin main` и GitHub Pages workflow.
