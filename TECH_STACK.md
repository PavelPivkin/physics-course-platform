# Технологический стек интерактивных материалов

Этот документ фиксирует текущую техническую основу интерактивных презентаций и
учебных материалов сайта/платформы. Стек не считается закрытым: его можно
расширять или пересматривать, когда существующих средств недостаточно для
конкретной педагогической или продуктовой задачи.

## 1. Назначение

На этом стеке создаются интерактивные материалы по физике для 7–11 классов,
включая подготовку к ОГЭ и ЕГЭ:

- управляемые преподавателем презентации;
- интерактивные объяснения на платформе;
- графики, схемы, модели и визуальные эксперименты;
- пошаговые решения задач;
- упражнения, тесты и демонстрационные материалы;
- повторно используемые учебные компоненты.

Материалы должны сочетать научную точность, педагогическую последовательность,
визуальное качество, интерактивность и устойчивую работу в браузере, в том числе
без подключения к интернету.

## 2. Базовый стек

| Технология | Назначение |
| --- | --- |
| **Reveal.js 5.x** | Движок презентаций, навигация, fragments, Auto-Animate, заметки и обзор |
| **React 19.x** | Компонентная архитектура, состояние и переиспользуемые учебные элементы |
| **TypeScript** | Типизация компонентов, физических моделей, заданий и данных |
| **Vite** | Локальная разработка, сборка и предпросмотр |
| **KaTeX** | Математическая типографика на основе LaTeX-синтаксиса |
| **SVG** | Векторные графики, схемы, иллюстрации и анимируемые элементы |
| **D3.js** | Шкалы, оси, формы и преобразование физических координат в экранные |
| **CSS / Web Animations API** | Темы, компоновка, переходы и управляемые анимации |

Использовать актуальные стабильные версии. Точные версии фиксируются в
`package-lock.json`; диапазоны в этом документе описывают выбранное поколение
технологий, а не заменяют lock-файл.

## 3. Разделение ответственности

### Reveal.js

Отвечает за структуру урока и темп объяснения:

- навигацию с клавиатуры и полноэкранный режим;
- пошаговое раскрытие через fragments;
- возврат к предыдущим этапам;
- Auto-Animate между связанными состояниями;
- заметки преподавателя и обзор презентации.

Ключевые этапы объяснения должны управляться преподавателем. Короткие
автоматические анимации допустимы внутри одного смыслового шага.

### React + TypeScript

Отвечают за компонентную систему, параметры, состояние и физические модели.
Предпочтительные базовые компоненты:

- `PhysicsPresentation`, `PhysicsSlide`;
- `Formula`, `FormulaStep`;
- `CoordinateSystem`, `FunctionGraph`;
- `VelocityTimeGraph`, `PositionTimeGraph`, `AccelerationTimeGraph`;
- `AreaUnderCurve`, `VectorArrow`, `PhysicsDiagram`;
- `StepReveal`, `ExerciseSlide`.

Компоненты должны быть параметризуемыми и повторно использоваться в разных
уроках. Физические величины, единицы, диапазоны и состояния описывать типами, а
не неявными строками и наборами несвязанных чисел.

### KaTeX

Все формулы, индексы, дроби, корни, векторы, греческие буквы и единицы измерения
оформляются через KaTeX. Математические обозначения на графиках также должны
использовать согласованный математический набор.

Формулы должны поддерживать смысловое выделение отдельных частей в соответствии
с цветовой семантикой из `STYLE_GUIDE.md`.

### SVG + D3.js

Графики и физические схемы преимущественно строятся в SVG. D3 применяется для
вычислений и геометрии (`d3-scale`, `d3-axis`, `d3-shape`), а React создаёт
SVG-элементы и управляет их состоянием.

Графические компоненты обязаны обеспечивать:

- математически корректные масштабы;
- оси, деления, подписи величин и единиц;
- вспомогательные линии, проекции и характерные точки;
- подсветку участков и площади под графиком;
- чёткость при масштабировании;
- различение физических случаев, например пути и перемещения при смене знака
  скорости.

### CSS и Web Animations API

CSS отвечает за темы, токены, сетку и базовые переходы. Web Animations API и
состояние React применяются для более сложных управляемых сцен. Анимация должна
соответствовать физической модели и корректно восстанавливаться при движении
назад.

## 4. Визуальная система

Единственным источником правил оформления является `STYLE_GUIDE.md`. Его
палитра, Rubik Light, типографика, цветовая семантика, композиция и характер
анимации имеют приоритет над общими цветовыми рекомендациями из исходного
описания технологического стека.

Технические компоненты не должны зашивать случайные цвета и размеры. Основные
токены темы следует хранить централизованно в CSS custom properties и
использовать в React, SVG и KaTeX-оформлении.

платформы, чтобы презентации не образовали изолированное приложение без общей
модели контента.

## 6. Сборка и автономная работа

Базовые команды:

```bash
npm install
npm run dev
npm run build
npm run preview
```

Обязательные свойства:

- статическая сборка HTML, CSS и JavaScript;
- локальный запуск и работа без интернета;
- локальное хранение шрифтов и обязательных ресурсов;
- совместимость с современными браузерами;
- полноэкранный режим и корректное масштабирование;
- отсутствие обязательных CDN-зависимостей во время урока;
- возможность экспорта в PDF как дополнительный, не основной режим.

## 7. Критерии качества

- Формулы профессионально набраны и единообразны.
- Графики физически и математически корректны.
- SVG остаётся чётким при масштабировании.
- Пошаговое объяснение управляется с клавиатуры.
- Возврат назад корректно восстанавливает состояние.
- Материал читается с последних парт и не перегружен.
- Анимации осмысленны и соответствуют физической модели.
- Материал работает без интернета после сборки.
- Компоненты пригодны для повторного использования и тестирования.
- Учебная логика отделена от визуального представления там, где это упрощает
  проверку и повторное использование.

## 8. Правило расширения стека

Новую библиотеку или технологию можно добавлять, если выполняется хотя бы одно
условие:

- текущий стек не решает необходимую задачу или решает её ненадёжно;
- собственная реализация будет заметно сложнее и дороже в сопровождении;
- новый инструмент существенно повышает доступность, производительность,
  тестируемость или качество физической визуализации.

Перед добавлением зафиксировать: решаемую проблему, рассмотренные альтернативы,
стоимость интеграции, влияние на офлайн-режим и размер сборки. Не добавлять
дублирующие библиотеки только ради удобства одного экрана.

## 9. Совместная физическая доска

Canvas платформы использует **Konva.js + TypeScript** для бесконечной доски и
**Matter.js** для механической симуляции выбранного физического фрейма. WebRTC
DataChannel отвечает за прямую синхронизацию преподавателя и ученика, небольшой
WebSocket-сервер используется только для signaling.

- Статический интерфейс можно публиковать на GitHub Pages.
- Signaling нельзя разместить на GitHub Pages; он запускается отдельно локально
  или публикуется как сервер с `wss://`.
- Для надёжного соединения через разные NAT и мобильные сети в production нужен
  TURN-сервер. STUN остаётся первым, но не единственным способом соединения.
- Источник истины — типизированная модель `BoardObject`, а не дерево Konva и не
  внутреннее состояние Matter.js.
- Konva отвечает только за камеру, слои, hit testing и отрисовку.
- Matter.js инкапсулирован в адаптере симуляции одного фрейма.
- Панели, поля ввода, tooltip, диалоги и будущий KaTeX остаются в DOM.
- D3 не используется в Canvas; он остаётся частью презентационного и
  графического стека там, где нужны шкалы, оси и SVG-графики.
- Предметные инструменты физики имеют приоритет над универсальными
  геометрическими примитивами.

Подробное состояние реализации, карта файлов, ограничения и план продолжения
зафиксированы в [`docs/PHYSICS_CANVAS.md`](docs/PHYSICS_CANVAS.md).

## 10. Главный принцип

Качество содержания, визуальная эстетика, наглядность и удобство восприятия
должны усиливать друг друга. Технология выбирается ради более точного и понятного
объяснения физики, а не ради демонстрации самой технологии.
